# Translation checklist — mechanically enumerated trap sites

Generated by sweeping `~/Development/reference-implementations/ttfx/src` (ttfx v0.3.1) for
constructs whose naive C# translation diverges. This exists because four rounds of human
review kept surfacing *instances* of the same handful of trap classes — the classes were
findable by review, but the full site lists are only findable by grep.

**How to use it.** When you port a file, look it up here first. Every site listed for that
file has a required C# form. When the pinned reference commit changes, re-run §9 and diff.

Counts are non-test code (`#[cfg(test)]` modules excluded where noted).

Two sites in §1 (`binarypath.rs:206`, `spotlights.rs:324`) were found by this sweep and by
none of the four reviews — which is the argument for the sweep.

---

## 1. Float → integer truncation (18 sites) — highest risk

Rust `as i64` on a float **truncates toward zero**. Not `Math.Round` (banker's), not
`Convert.ToInt64` (rounds). Most of these compute a *count*, so rounding instead of truncating
changes how many RNG draws follow and desynchronizes the rest of the run.

**Required form:** `PyCompat.TruncToI64(double)`.

| Site | Expression |
|---|---|
| `utils/easing.rs:356` | `(eased_value * seq_len as f64) as i64 as usize` |
| `utils/easing.rs:357` | `(previous_eased * seq_len as f64) as i64 as usize` |
| `utils/graphics.rs:361` | `(v * 255.0) as i64` — Python `int()`, deliberately not `round` |
| `utils/geometry.rs:88` | `(b_squared * (1.0 - x_component)).powf(0.5) as i64` |
| `effects/colorshift.rs:167` | `(spectrum.len() as f64 * direction_index) as i64` |
| `effects/orbittingvolley.rs:158` | `(canvas_top as f64 * parent_progress) as i64` |
| `effects/orbittingvolley.rs:163` | `(canvas_right as f64 * parent_progress) as i64` |
| `effects/orbittingvolley.rs:168` | `(canvas_top as f64 * parent_progress) as i64` |
| `effects/orbittingvolley.rs:368` | `((volley_size * input_len as f64) / 4.0) as i64` |
| `effects/matrix.rs:165` | `(characters.len() as f64 * 0.1) as i64` |
| `effects/binarypath.rs:206` | `(canvas.right as f64 * 0.2) as i64` |
| `effects/binarypath.rs:354` | `(active_binary_groups * pending.len() as f64) as i64` |
| `effects/spotlights.rs:324` | `.min(smallest_dimension as f64) as i64` |
| `effects/bouncyballs.rs:187` | `(canvas_top as f64 * rng.uniform(1.0, 1.5)) as i64` |
| `effects/random_sequence.rs:72` | `(speed * input_len as f64) as i64` |
| `effects/spray.rs:222` | `(pending.len() as f64 * spray_volume) as i64` |
| `effects/errorcorrect.rs:381` | `(error_pairs * characters.len() as f64) as i64` |
| `effects/fireworks.rs:413` | `(launch_delay as f64 * rng.uniform(0.5, 1.5)) as i64` |

**Special case — the double cast.** `easing.rs:356-357` is `as i64 as usize`: a negative eased
value (overshoot easings produce them) truncates to a negative `i64` and then *wraps* to a huge
`usize`. C# `(long)` then `(int)` does something else, and a `checked` context throws.
Transcribe both steps deliberately with `unchecked`.

The other 49 `as i64` occurrences are `.len() as i64` integer widening — harmless.

## 2. Float functions that must not be "simplified" (47 sites)

**`.powf(`** — 55 calls across 44 lines. Exponent frequency: `2.0`×28, `3.0`×8, `5.0`×4,
`4.0`×4, `0.5`×3, plus 8 variable-exponent calls (`2.0_f64.powf(10.0 * p - 10.0)` etc.).

- `utils/easing.rs` — 38 lines (every polynomial, exponential, elastic, bounce, back easing,
  and the CubicBezier sampler at `:246-249`)
- `utils/geometry.rs:84, 85, 87, 88, 233, 234`

**Required:** `Math.Pow(x, 2.0)` — **never** `x * x`, and `Math.Pow(x, 0.5)` — **never**
`Math.Sqrt(x)`. `Math.Sqrt` is correctly rounded and `Math.Pow` is not; they differ in the
last ulp, and `geometry.rs:88`/`:233-234` feed coordinate quantization where that flips a cell.

**`f64::hypot`** — `utils/geometry.rs:204, 206`. Required: `double.Hypot`, never
`Math.Sqrt(x*x + y*y)` (different overflow behavior and rounding).

**Float `.min()` / `.max()`** — Rust returns the **non-NaN** operand; .NET's `Math.Min`/`Math.Max`
**propagate** NaN, and they differ on signed zero. Required: `PyCompat.FMin`/`FMax`.

| Site | Expression |
|---|---|
| `utils/easing.rs:306` | `.min(1.0).max(0.0)` clamp |
| `engine/ctx.rs:411` | `(distance_to_travel / seg_distance).min(1.0)` |
| `engine/ctx.rs:604, 605, 606` | `.max(1.0)` guards in the synced-scene formulas |
| `engine/animation.rs:588, 589` | HSL `max_val` / `min_val` chains |
| `engine/animation.rs:613` | `(lightness * brightness).min(1.0).max(0.0)` |
| `effects/spotlights.rs:235` | `.max(0.2)` |
| `effects/spotlights.rs:324` | `.min(smallest_dimension as f64)` |

Iterator `.min()`/`.max()` on integers (`canvas.rs:109-154`, `input.rs:75-100`,
`terminal.rs:481, 779`, `print_effect.rs:120, 339`, `bubbles.rs:156`) are `Ord`-based —
LINQ `Min()`/`Max()` is fine. Note they `.unwrap()` on empty; see §7.

## 3. Exact float equality (17 sites) — do not add an epsilon

Every one is a branch guard. An epsilon changes which branch runs.

- `utils/easing.rs:130, 137, 144, 146, 184, 186, 194, 196, 204, 206` — `p == 0.0` / `p == 1.0`
  short-circuits in the exponential and elastic easings
- `engine/animation.rs:593, 602, 604, 615` — HSL: `max_val == min_val`,
  `max_val == normalized_red`, `max_val == normalized_green`, `saturation == 0.0`. Result feeds
  `round_half_even(channel * 255)`, so a flipped branch is a visible colour change
- `engine/ctx.rs:328` (`total_distance == 0.0`), `:406` (`seg_distance == 0.0`)
- `utils/geometry.rs:134` (`total_distance == 0.0`)

### 4a. RNG-indexed removals (11 sites) — the ones that desynchronize

Each is `remove(<index drawn from rng>)`, shifting the tail. `List.RemoveAt(i)` is correct.
`Remove(value)` (removes the first *equal* element) or a swap-removal changes which element

### 4b. `remove(0)` FIFO drains (~40 sites)

`List.RemoveAt(0)` is correct (O(n), irrelevant at terminal scale). Files: `beams`,
`binarypath`, `blackhole`, `bubbles`, `burn`, `crumble`, `decrypt`, `errorcorrect`,
`laseretch`, `matrix`, `orbittingvolley`, `pour`, `print_effect`, `rain`, `slice`, `slide`,
`spanning_tree:317`, `synthgrid`, `thunderstorm`, `waves`.

### 4c. `swap_remove` (1 site)

`engine/terminal.rs:336` — `visible_characters.swap_remove(position)`. Removes by swapping in
the **last** element. **Currently latent**: the painter does not sort, it walks and keeps the
max `(layer, character_id)` per cell (`terminal.rs:527-548`), so iteration order does not reach
output. Implement swap-removal anyway — it is what the reference does, and a future
"sort then paint" would expose the divergence.

### 4e. Keyed removal from an insertion-ordered map (1 site)

`effects/rings.rs:117` — `ch.motion.paths.remove("disperse")`. This is the one place a
`Dictionary`'s "iteration order breaks on removal" behavior would actually bite, since
`motion.paths` is iterated elsewhere. `OrderedMap.Remove` must preserve the order of the
remaining entries.

### 4f. Stable sorts (11 sites)

Rust uses `sort_by`/`sort_by_key` (stable) at all 11; `sort_unstable` at zero.
`List<T>.Sort`/`Array.Sort` are **unstable**. Required: `OrderBy` or `Sorting.StableSort`.

`utils/spanning_tree.rs:152` · `engine/terminal.rs:353, 356, 390, 399, 428, 503` ·
`effects/beams.rs:134, 137` · `effects/rain.rs:219` · `effects/bouncyballs.rs:215`

### Other string sites

- `engine/input.rs:63` — `sequence.starts_with("\x1b[")`, and `:337` — `starts_with('?')`.
  Required: `StringComparison.Ordinal` (C# `StartsWith(string)` is culture-sensitive).

  `ToLowerInvariant`.
- `engine/terminal.rs:708` — `parse::<i64>()` on `COLUMNS`/`LINES`. Rust rejects surrounding

  length and cannot be used.
- `utils/graphics.rs:361-364` — negative components format as `"-3"`, not two's complement.
  C# `i.ToString("x2")` on a negative int gives `fffffffd`.

## 6. `str::len()` is bytes

181 `.len()` occurrences, the overwhelming majority `Vec::len` (→ `.Count`, fine). The byte-
semantic ones cluster in: the frame length prefix (`engine/effect.rs`), `FormattedSymbol`'s
capacity check (`engine/animation.rs`), and `Cli::parse_color`'s `s.len() <= 3` (ASCII-safe by
construction). Building frames as `byte[]` (plan §5.7) removes most of these.

## 7. Panic sites (non-test)

`assert!`/`assert_eq!`: **6** · `.expect(...)`: **110** · `.unwrap()`: **370** · `panic!`: 0.

The release profile is `panic = "abort"` (`Cargo.toml:17`), so these die from `SIGABRT`. Per
plan §5.6 they map to an uncaught `EngineInvariantException` — the requirement is that they
**throw**, never silently return a default or a clamped value. Highest-value ones to test
explicitly: `rng.rs:59-85` (`randbelow(0)`, empty `choice`, inverted `randint`),
`terminal.rs:516-519`, `ctx.rs:256-257` (`activate_path` on a missing/empty path),
`binarypath.rs:159` (`"empty symbol"`), `swarm.rs:113` (`"path id must start with a digit"`).

Note the iterator `.min()/.max().unwrap()` sites in §2 panic on empty input — LINQ
`Min()`/`Max()` throw `InvalidOperationException` there, which is the matching behavior.

---

## 8. Integer widths

`i64` → `long`, `u64` → `ulong` throughout (seeds `cli.rs:125`, `max_frames`). Coordinates,
counts and delays are `i64`. `List.Count` staying `int` is fine. `rng.rs:73, 79` do
`(b - a + 1) as u64` arithmetic that behaves differently on `int`.

## 9. Regenerating this file

Run against a fresh reference checkout after a version bump and diff:

```sh
cd <reference>/src
grep -rnE '\bas i64\b' .                                  # §1  (filter to float sources)
grep -rnE '\.powf\(|hypot' .                              # §2
grep -rnE '\.(min|max)\(' .                               # §2  (filter to float receivers)
grep -rnE '[a-z_\)]+ *[=!]= *[0-9]+\.[0-9]' .             # §3
grep -rnE '\.remove\(' .                                  # §4a/4b (classify by index source)
grep -rn  'swap_remove' .                                 # §4c
grep -rnE 'VecDeque|push_front|push_back|pop_front|pop_back|\.front\(|\.back\(' .   # §4d
grep -rnE '\.sort(_by|_by_key|_unstable[a-z_]*)?\(' .     # §4f
grep -rn  '\.chars()' .                                   # §5
grep -rnE 'starts_with|ends_with|to_(lower|upper)case|to_digit|parse::<' .          # §5
grep -rnE '\bassert(_eq)?!|\.expect\(|\.unwrap\(\)' .     # §7
```

A new site appearing in any class is a porting task, not a surprise.
